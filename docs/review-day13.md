## 2. Конкретные замечания и рекомендации по результатам ревью

### Комментарий 1: Оформление и аннотирование релизного тега v1.0
- **Категория:** Релизный процесс и Git Tags
- **Суть замечания:**
  В репозитории команды создан легковесный (lightweight) тег вместо аннотированного (annotated). Легковесный тег не сохраняет дату создания, имя автора релиза и развернутое релизное сообщение, что усложняет аудит версий в CI/CD пайплайнах.
- **Рекомендация:**
  Использовать команду создания аннотированного тега с ключом `-a` и подробным сообщением:  
  `git tag -a v1.0 -m "Релиз v1.0: Полнофункциональная система бронирования OrbitPark MVP"`.

---

### Комментарий 2: Соответствие структуры CHANGELOG.md стандарту Keep a Changelog
- **Категория:** Документирование релизов
- **Суть замечания:**
  В файле `CHANGELOG.md` версии 1.0.0 разделы «Добавлено» и «Исправлено» объединены в единый сплошной список. Стандарт [Keep a Changelog](https://keepachangelog.com/) требует строгого деления на секции: `Added` (Добавлено), `Changed` (Изменено), `Deprecated` (Устарело), `Removed` (Удалено), `Fixed` (Исправлено) и `Security` (Безопасность).
- **Рекомендация:**
  Разбить изменения на тематические секции `### Добавлено`, `### Исправлено` и `### Изменено` для удобства чтения пользователями и заказчиками.

---

### Комментарий 3: Документирование контекста конфликта слияния
- **Категория:** Разрешение конфликтов (Merge Conflicts)
- **Суть замечания:**
  В описании конфликта в `docs/git-strategy.md` приведены маркеры `<<<<<<< HEAD` и `>>>>>>> feature/booking-v2`, но не указан хэш результирующего коммита слияния (Merge Commit SHA-1) и не приведена команда валидации тестов после разрешения конфликта.
- **Рекомендация:**
  Всегда указывать хэш коммита слияния (например, `Merge commit '5b7e31d'`) и явно фиксировать шаг повторного прогона `npm test` для подтверждения отсутствия регрессий в коде после слияния.

---

### Комментарий 4: Конфигурация базового пути (Base Path) для GitHub Pages
- **Категория:** Развертывание (Deployment)
- **Суть замечания:**
  При сборке SPA-приложения на Vite для GitHub Pages без указания свойства `base: '/repo-name/'` в файле `vite.config.js`, абсолютные пути к статическим ресурсам (`/assets/index.js`) ведут к ошибкам 404 на домене `username.github.io/repo-name/`.
- **Рекомендация:**
  Убедиться, что в `vite.config.js` задан корректный `base: './'` или `base: '/orbit-park/'` для корректной подгрузки скриптов и стилей.
