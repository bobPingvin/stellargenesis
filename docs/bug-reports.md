### BR-01: Отсутствие механизма сохранения и восстановления состояния системы в LocalStorage
- **Связанный тест-кейс:** TC-21 (Сохранение и восстановление состояния из LocalStorage)
- **Приоритет:** Критический (Critical)
- **Предусловие:** Пользователь создал собственную конфигурацию звездной системы.
- **Шаги воспроизведения:**
  1. Создать в симуляторе бинарную систему из двух звезд и трех планет.
  2. Перезагрузить страницу браузера (`F5`).
- **Ожидаемый результат:** Пользовательская система считывается из локального хранилища и восстанавливается на экране.
- **Фактический результат:** В исходной сборке симулятор всегда принудительно вызывал `loadPreset('solar')` при монтировании компонента, а кнопки сохранения отсутствовали в интерфейсе.
- **Причина дефекта:** В компонентах `App.tsx` и `TopNavigation.tsx` не были реализованы функции сериализации снимка тел в JSON и обработчик записи в `localStorage`.
- **Способ устранения:**
  1. В `src/App.tsx` добавлены функции `handleSaveStorage` и `handleLoadStorage` с записью снимка в ключ `stellargenesis_custom_save_v1` с защитой от переполнения квоты:
     ```typescript
     const handleSaveStorage = useCallback(() => {
       try {
         const payload = {
           version: 1,
           timestamp: Date.now(),
           preset: currentPreset,
           bodies: bodiesRef.current,
           particles: particlesRef.current.slice(0, 300),
           camera,
           settings
         };
         localStorage.setItem(STORAGE_KEY, JSON.stringify(payload));
         setHasSavedStorage(true);
         sound.playMassPump();
         addToast('💾 Сохранено в LocalStorage', `Снимок системы сохранен.`, 'info');
       } catch (err: any) {
         addToast('⚠️ Ошибка сохранения', err?.message, 'warning');
       }
     }, [currentPreset, camera, settings, addToast]);
     ```
  2. В верхний HUD (`TopNavigation.tsx`) добавлены кнопки «Сохранить» (`Save`) и «Загрузить» (`FolderDown`), а также клавиатурное сочетание `Ctrl + S`.
- **Статус:** ✅ Исправлено (проверено регрессионным тестом TC-21)
- **Исполнитель:** Журавлёв М.

### BR-02: Горизонтальный скролл и перекрытие кнопок панели QuickDock на экранах 320px
- **Связанный тест-кейс:** TC-23 (Адаптивное отображение интерфейса на мобильном экране 320px)
- **Приоритет:** Средний (Medium / UI-UX)
- **Предусловие:** Открыта вкладка браузера в режиме DevTools Device Toolbar с разрешением $320 \times 568$ (iPhone SE).
- **Шаги воспроизведения:**
  1. Открыть симулятор на ширине 320px.
  2. Выбрать небесное тело, чтобы активировался QuickDock.
- **Ожидаемый результат:** Нижний док умещается по ширине экрана, горизонтальная прокрутка отсутствует, все кнопки кликабельны.
- **Фактический результат:** Панель с фиксированными паддингами выходила за правый край экрана ($360\text{px} > 320\text{px}$), вызывая появление горизонтального скроллбара.
- **Причина дефекта:** Использование фиксированных ширин контейнера и отсутствие адаптивных медиа-запросов Tailwind (`max-w-[calc(100vw-1rem)]`, `overflow-x-auto`).
- **Способ устранения:**
  Контейнер QuickDock переведен на адаптивную сетку с динамическим сжатием текстовых ярлыков:
  ```tsx
  <div className="flex items-center gap-1.5 px-2 py-1.5 max-w-[calc(100vw-1rem)] overflow-x-auto no-scrollbar rounded-2xl glass-panel">
    {/* Иконки с touch-target 40px и скрытием длинного текста на мобильных */}
  </div>
  ```
- **Статус:** ✅ Исправлено (проверено регрессионным тестом TC-23)
- **Исполнитель:** Журавлёв М.

### BR-03: Ложное срабатывание зума/3D при микроперемещении курсора во время клика по телу
- **Сценарий/Тест-кейс:** TC-09 (Отсутствие ложного перехода в 3D при простом клике по объекту)
- **Приоритет:** Высокий (High / Event Collision)
- **Предусловие:** Симулятор запущен, планеты обращаются по орбитам.
- **Шаги воспроизведения:**
  1. Навести курсор на быстро движущуюся планету (например, Меркурий).
  2. Нажать ЛКМ с естественным микродрожанием руки (смещение на 1–2 пикселя до `mouseup`).
- **Ожидаемый результат:** Выделяется планета и открывается карточка `StarInspector`.
- **Фактический результат:** Обработчик Canvas трактовал микросмещение как жест панорамирования холста (`drag-pan`), сбрасывал выбранное тело или вызывал рассинхронизацию координат.
- **Причина дефекта:** Отсутствие порога нечувствительности перемещения мыши (`drag threshold`) при определении одиночного клика.
- **Способ устранения:**
  В `CanvasViewport.tsx` внедрена проверка гипотенузы перемещения между `mousedown` и `mouseup`:
  ```typescript
  const dragDistance = Math.hypot(currentX - startX, currentY - startY);
  const clickDuration = Date.now() - clickStartTime;

  if (dragDistance < 4.0 && clickDuration < 250) {
    // Строго одиночный клик выбора тела
    handleSelectBodyAt(currentX, currentY);
  } else {
    // Панорамирование камеры
    updateCameraPan();
  }
  ```
- **Статус:** ✅ Исправлено (проверено регрессионным тестом TC-09)
- **Исполнитель:** Журавлёв М.

### BR-04: Предупреждение `AudioContext was not allowed to start` при генерации звука
- **Сценарий/Тест-кейс:** TC-22 (Аудиосистема)
- **Приоритет:** Средний (Medium / Console Cleanliness)
- **Предусловие:** Пользователь впервые открыл страницу симулятора и не совершал кликов по экрану.
- **Шаги воспроизведения:**
  1. Дождаться автоматического взрыва массивной звезды в процессе фоновой эволюции.
- **Ожидаемый результат:** Звук воспроизводится штатно либо тихо ждет взаимодействия пользователя. В консоли отсутствуют неперехваченные предупреждения.
- **Фактический результат:** Браузер Chromium блокировал генерацию аудиопотока и выбрасывал в консоль: `The AudioContext was not allowed to start. It must be resumed (or created) after a user gesture on the page.`
- **Причина дефекта:** Попытка прямого вызова методов узла осциллятора при состоянии `AudioContext.state === 'suspended'` без предварительного вызова `ctx.resume()`.
- **Способ устранения:**
  В модуле `src/physics/audio.ts` инициализация контекста обернута в ленивый резолвер по первому пользовательскому жесту:
  ```typescript
  export function ensureAudioContextReady() {
    if (!audioCtx) {
      audioCtx = new (window.AudioContext || (window as any).webkitAudioContext)();
    }
    if (audioCtx.state === 'suspended') {
      audioCtx.resume().catch(() => {});
    }
    return audioCtx;
  }
  ```
- **Статус:** ✅ Исправлено (проверено регрессионным тестом TC-22)
- **Исполнитель:** Журавлёв М.

### BR-05: Рассинхронизация константы $c$ (60.0 px/s) и отсутствие жесткого зажима скорости
- **Сценарий/Тест-кейс:** TC-27 (Экстремальная масса и релятивистский лимит скорости)
- **Приоритет:** Критический (Critical / Math Engine)
- **Предусловие:** В систему помещена черная дыра массой $10^{12}\ M_\odot$.
- **Шаги воспроизведения:**
  1. Запустить расчет движения спутников вблизи горизонта событий.
  2. Замерить скорость свободного падения тела.
- **Ожидаемый результат:** Скорость тел строго ограничена константой `SPEED_OF_LIGHT = 60.0 px/s`, объявленной в `src/physics/engine.ts`.
- **Фактический результат:** В документации ошибочно заявлялось значение $c = 300$, а в цикле физики `stepPhysics` ускорение не отсекалось по константе, что приводило к телепортации тел за границы вселенной при экстремальных массах.
- **Причина дефекта:** Рассинхронизация спецификации с кодовой базой и отсутствие шага релятивистского отсечения скорости на втором полушаге Верле.
- **Способ устранения:**
  1. В `src/physics/engine.ts` на 3-м шаге `stepPhysics` внедрен инвариант:
     ```typescript
     // Relativistic velocity clamping: v <= SPEED_OF_LIGHT (60.0 px/s)
     const speed = Math.hypot(b.vx, b.vy);
     if (speed > SPEED_OF_LIGHT) {
       const factor = SPEED_OF_LIGHT / speed;
       b.vx *= factor;
       b.vy *= factor;
     }
     ```
  2. В `docs/test-cases.md` скорректировано значение константы на $60.0\text{ px/s}$.
  3. Создан юнит-тест стенд `tests/physics.test.ts`, подтверждающий соблюдение порога скорости с машинной точностью.
- **Статус:** ✅ Исправлено (проверено юнит-тестом `npm test` и регрессионным тестом TC-27)
- **Исполнитель:** Журавлёв М.
