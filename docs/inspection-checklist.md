## 1. Именование (Naming Conventions)
- [x] Переменные в camelCase (`orbitalSpeed`, `tidalRadius`, `selectedBodyId`).
- [x] Функции и методы в camelCase (`computeDopplerFromVx`, `stepPhysics`, `createBody`).
- [x] Классы и интерфейсы в PascalCase (`CelestialBody`, `SimulationSettings`, `SoundEngine`).
- [x] Глобальные физические и математические константы в UPPER_SNAKE_CASE (`SPEED_OF_LIGHT`, `CHANDRASEKHAR_LIMIT`, `TOV_LIMIT`, `ACCRETION_EFFICIENCY`, `MAX_TIDAL_STRETCH_FACTOR`).
- [x] Имена файлов и модулей в camelCase/kebab-case (`celestialScales.ts`, `blackHole3DRenderer.ts`, `test-coverage.md`).
- [x] Имена осмысленные и семантические (устранены однобуквенные сокращения вроде `b`, `f`, `sc` в пользу `body`, `forceScalar`, `filamentIndex`).

## 2. Структура кода (Code Structure & Formatting)
- [x] Единообразные отступы 2 пробела по всему проекту.
- [x] Отсутствие чрезмерно длинных строк (> 120 символов без переноса).
- [x] Функции декомпозированы и обозримы (крупная функция `computeAccelerations` декомпозирована на специализированные обработчики `handleTidalDisruptionEvent` и `handleInelasticBodyCollision`).
- [x] Глубина вложенности циклов и условий не превышает 3 уровней.
- [x] Отсутствие дублирования кода (выделен общий алгоритм `computeSingleBodyTidalStretch` для симметричного расчета приливных сил).

## 3. Комментарии и документация (Comments & TSDoc)
- [x] Наличие формализованных JSDoc/TSDoc спецификаций с `@param`, `@returns` для всех публичных экспортируемых функций ядра.
- [x] Сложные релятивистские и гидродинамические уравнения снабжены поясняющими комментариями со ссылками на формулы (пределы Роша, метрика Шварцшильда, симплектический алгоритм Верле).

## 4. Константы и «магические числа» (Magic Numbers)
- [x] Отсутствие «магических чисел» в формулах слияния и приливного разрушения (коэффициенты `0.85`, `0.90`, `6.5`, `25.0`, `12.0` вынесены в именованные константы).
