# Руководство по установке и развёртыванию (Installation & Deployment Guide)
## StellarGenesis — Интерактивный симулятор релятивистской астрофизики и звездной эволюции

**Версия:** 1.0 (MVP Release)  
**Дата:** 07 октября 2026 г. (07.10.2026)  
**Репозиторий:** [github.com/bobPingvin/stellargenesis](https://github.com/bobPingvin/stellargenesis)

---

## 1. Системные требования

### 1.1. Клиентские требования (для пользователей)
- **Веб-браузер:** Любой современный браузер с аппаратной поддержкой **WebGL 2.0** и **Web Audio API**:
  - Google Chrome / Chromium $\ge 120$ (рекомендуется);
  - Mozilla Firefox $\ge 125$;
  - Apple Safari $\ge 17.0$;
  - Microsoft Edge $\ge 120$.
- **Аппаратные ресурсы:**
  - Процессор: 2+ ядра с частотой от 2.0 ГГц;
  - Оперативная память: от 4 ГБ RAM;
  - Видеокарта: интегрированная или дискретная с поддержкой OpenGL ES 3.0 / WebGL 2.0;
  - Экран: разрешение от 320px (смартфоны) до 4K (десктопы).

### 1.2. Требования к среде разработки (для сборки из исходников)
- **Node.js:** версия `v18.18.0` или `v20.x` LTS (рекомендуется Node.js 20+);
- **Менеджер пакетов:** `npm` версии $\ge 9.0$ (или `bun` / `pnpm` / `yarn`);
- **Система контроля версий:** `Git` версии $\ge 2.30$;
- **Операционная система:** Linux (Ubuntu/Debian/Arch), macOS (12+), Windows 10/11 (PowerShell или WSL2).

## 2. Локальная установка и запуск

Пошаговый процесс развертывания проекта на локальном компьютере разработчика:

```bash
# Шаг 1. Клонирование репозитория
git clone https://github.com/bobPingvin/stellargenesis.git

# Шаг 2. Переход в директорию проекта
cd stellargenesis

# Шаг 3. Установка npm-зависимостей
npm install

# Шаг 4. Запуск локального сервера разработки в режиме горячей перезагрузки (HMR)
npm run dev
```

После успешного выполнения команды в терминале появится сообщение:
```text
  VITE v8.3.1  ready in 240 ms

  ➜  Local:   http://localhost:3000/
  ➜  Network: http://192.168.1.100:3000/
  ➜  press h + enter to show help
```

Откройте в браузере адрес **`http://localhost:3000`** для работы с симулятором.

## 3. Конфигурация проекта

### 3.1. Переменные окружения (`.env.example`)
В корневой папке проекта расположен файл `.env.example`. При необходимости скопируйте его в `.env`:
```bash
cp .env.example .env
```
Параметры окружения:
```ini
# Порт локального dev-сервера (по умолчанию 3000)
PORT=3000

# Режим окружения (development / production)
NODE_ENV=development
```

### 3.2. Конфигурационные файлы
- **`vite.config.ts`:** Конфигурация сборщика Vite 8 с плагином React 19 и Tailwind CSS v4:
  - Сервер настроен на порт `3000` с доступом по локальной сети (`host: '0.0.0.0'`);
  - Поддерживается базовый путь для развертывания на GitHub Pages (`base: './'`).
- **`vitest.config.ts`:** Настройки тестового фреймворка Vitest:
  - Провайдер покрытия: `v8`;
  - Изоляция воркеров и окружение `node` для математического ядра.
- **`tsconfig.json`:** Строгая статическая типизация TypeScript 5.8 (`strict: true`, `noImplicitAny: true`, `target: ESNext`).

## 4. Сборка для продакшна и варианты развёртывания

### 4.1. Сборка статического продакшн-бандла
```bash
npm run build
```
Результат сборки помещается в директорию `dist/`:
- `dist/index.html` (~1.7 KB) — корневой HTML-файл;
- `dist/assets/index-*.css` (~9.8 KB gzip) — скомпилированные стили Tailwind CSS;
- `dist/assets/index-*.js` (~199 KB gzip) — минифицированный JavaScript бандл с чистым ядром.

Проверить собранный продакшн-бандл локально:
```bash
npm run preview
```

---

### 4.2. Развёртывание на GitHub Pages
1. Убедитесь, что в `vite.config.ts` указан относительный путь `base: './'`.
2. Выполните сборку: `npm run build`.
3. В настройках вашего репозитория на GitHub:
   - Перейдите в **Settings** $\to$ **Pages**;
   - В разделе **Build and deployment** выберите **Source: Deploy from a branch**;
   - Укажите ветку `main` (или `gh-pages`) и папку `/root` или `/dist`;
   - Сохраните настройки. Сайт станет доступен по адресу `https://<username>.github.io/<repo-name>/`.

---

### 4.3. Развёртывание через Docker / Nginx
Для запуска в изолированном контейнере создайте `Dockerfile`:
```dockerfile
# Stage 1: Сборка
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Раздача статики через Nginx
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

Команды сборки и запуска контейнера:
```bash
docker build -t stellargenesis:1.0 .
docker run -d -p 8080:80 --name stellargenesis stellargenesis:1.0
```
Приложение будет доступно по адресу `http://localhost:8080`.

## 5. Тестирование и контроль качества

Перед публикацией или внесением изменений выполните полный цикл проверок:

```bash
# 1. Запуск unit-тестов Vitest (38 тестов)
npm test

# 2. Инструментальный сбор покрытия кода (v8 coverage)
npm run test:coverage

# 3. Валидация статических типов TypeScript (Typecheck)
npm run lint

# 4. Проверочная сборка продакшн-бандла
npm run build
```

## 6. Решение типичных проблем (Troubleshooting)

| Проблема / Симптом | Причина | Инженерное решение |
|:---|:---|:---|
| **`Error: listen EADDRINUSE: address already in use :::3000`** | Порт 3000 занят другим процессом | Завершите процесс: `npx kill-port 3000` или укажите другой порт: `npm run dev -- --port 3001`. |
| **`MISSING DEPENDENCY @vitest/coverage-v8`** | Не установлен пакет провайдера покрытия | Выполните установку: `npm install -D @vitest/coverage-v8`. |
| **Нет звука при старте симулятора** | Браузерная политика Autoplay Policy блокирует аудио до клика | Кликните в любое место экрана симулятора или нажмите кнопку `🔊` в правом верхнем углу. |
| **`WebGL context lost` в 3D окне** | Недостаток видеопамяти или сбой видеодрайвера | Закройте ресурсоемкие вкладки с WebGL, обновите драйвер видеокарты или перезагрузите страницу. |
| **Снижение FPS при симуляции 500+ частиц** | Высокая нагрузка на отрисовку трейлов на слабых GPU | Отключите опцию «Орбитальные трейлы» (Trails) в верхнем тулбаре симулятора. |
| **Ошибки 404 к файлам стилей на GitHub Pages** | Некорректный абсолютный базовый путь | Проверьте, что в `vite.config.ts` выставлено свойство `base: './'`. |
